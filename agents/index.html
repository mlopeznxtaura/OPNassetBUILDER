What this is

OPNassetBUILDER (app14): Stage 1 design (voxels, sprites, characters, Scan 360 → voxel hull), Stage 2 world placement. Each browser session gets its own library via POST /api/sessions and a Durable Object keyed by sessionId. Large GLBs go to /api/blobs/… (tiered storage: Supabase, S3, R2 last — see STORAGE_TIERS), not inside library JSON (~800 KB cap).

Platform plan: docs/PLATFORM_PLAN.md · Storage setup: docs/STORAGE_SETUP.md · Kit exports: KIT_AND_ENGINE_EXPORT.md

Export profiles (web vs engine)

ProfilePatternRegister as
web*_web.glbcharacter.src or kit.derivatives.web — preview in Design/World
engine*_engine.glbkit.derivatives.engine — Unreal/Unity; never browser viewport

Build both: python scripts/build_characters.py --out assets. MCP upsert_asset with kind:"kit" and derivatives shorthand is in agent.json → asset_kinds.kit.export_profiles.

Sessions & blobs

  • POST /api/sessions — new studio; sets gf_session cookie; returns sessionId
  • X-GameForge-Session — send on /api/* and /mcp (browser sets this after session create)
  • PUT /api/blobs/{sessionId}/name.glb — upload mesh (≤25 MB). Use web GLB for preview; engine GLB for Unreal/Unity.
  • POST /api/blobs/{sessionId}/file.glb/upload-url — presigned upload (~15 min)

MCP

POST JSON-RPC 2.0 to /mcp. Methods: initialize, tools/list, tools/call. Use the same session as the UI.

curl -sS https://YOUR_HOST/mcp \
  -H 'content-type: application/json' \
  -H 'x-gameforge-session: s_YOUR_SESSION' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

Stdio: GAMEFORGE_ORIGIN + GAMEFORGE_SESSION → node mcp/stdio.js

Asset kinds

  • voxel — grid of colored cubes; paint_voxels or upsert_asset with cells. Optional seedStarter for name-based starter mesh.
  • sprite — 2D pixel grid; paint_sprite.
  • character — character.src must be a web GLB (/assets/*_web.glb or blob). Presets female-hero / male-hero are catalog pointers only.
  • kit — kit.derivatives.web (preview) + kit.derivatives.engine (Unreal/Unity parts). Build: python scripts/build_characters.py --out assets. KIT_AND_ENGINE_EXPORT.md
  • scan — Scan 360: video, frame decode, visual-hull voxel bake; save stores thumbnail + frameCount / hullVoxels.

REST

  • POST /api/sessions · PUT/GET /api/blobs/…
  • GET /api/state — library + level + revision
  • POST /api/assets — upsert asset JSON body
  • POST /api/level/placements — add placement or {op:"remove",id}
  • POST /api/test — validation + collision probes
